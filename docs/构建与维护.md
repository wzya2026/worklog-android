# 构建与维护

## 构建环境

- Windows PowerShell 7（Windows PowerShell 5.1 亦可运行本脚本）。
- JDK 17；设置 `JAVA_HOME`，或通过 `-JavaHome` 指定。
- Android SDK Platform 35 和 Build Tools 35.0.0；设置 `ANDROID_HOME`，或通过 `-AndroidSdk` 指定。

```powershell
./build.ps1 -Variant FullScreen
./build.ps1 -Variant NavKeys
./build.ps1 -Variant TabletAdaptive
```

没有提供签名信息时生成未签名 APK，不能直接安装。每次构建使用独立的 `.build/` 目录；不会清理原项目或历史 APK。

## 签名

原签名密钥不在公开仓库。签名构建需要自己保管的密钥文件，密码通过环境变量传递，不写进脚本或命令参数：

```powershell
# 先在本机安全地设置 WORKLOG_STORE_PASSWORD 和 WORKLOG_KEY_PASSWORD，切勿提交到 Git。
./build.ps1 -Variant FullScreen -KeyStore '你的私有密钥路径' -KeyAlias '你的别名'
```

使用其他密钥签名的包无法覆盖现有原签名安装。不要为绕过签名冲突直接卸载正在使用的 APP；应先导出并妥善备份数据。

## 维护约定

- 保留历史 APK、原始源码和签名密钥，不清空旧输出目录。
- 继续沿用既有版本命名规则；修改后核对 `versionName`、`versionCode` 及发布说明。
- 三个布局共用应用代码，仅通过 Manifest 的 `NAV_KEYS_LAYOUT`、`TABLET_LAYOUT` 和旋转配置区分。
- 平板版尊重系统自动旋转，不因旋转重建页面而丢失正在输入的内容。
- 只有用户明确提出新功能时再开发；本次没有实现 NAS 合并同步或桌面版本。

## 已做的发布检查

使用原 Android SDK 的 `aapt` 读取原始 APK 的版本、权限及布局开关，使用 `apksigner verify` 验证原有签名；ZIP 检查与 SHA256 也通过。源码与原项目文件逐一核对。此处没有把这些静态检查表述为手机真机使用测试。
